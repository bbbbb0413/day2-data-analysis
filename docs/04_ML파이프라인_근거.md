## 1. STEP 1 결정의 요약 (재확인)

구현 시 반드시 지켜야 하는 세 가지만 다시 적는다.

### 모집단을 카드결제로 한정한다

| `payment_type` | 건수 | 팁 = 0 비율 |
|---|---:|---:|
| 1 (카드) | 2,660,701 | 9.8% |
| 2 (현금) | 350,545 | **100.0%** |
| 3·4 (무료·분쟁) | 10,213 | **100.0%** |

현금 결제는 팁이 예외 없이 0으로 기록된다. 승객이 안 준 게 아니라 현금 팁이
미터기에 입력되지 않기 때문이다. 섞어서 학습하면 모델이 **"결제수단 맞히기"**를
하게 되고, 정확도는 높게 나오지만 팁에 대해 아무것도 예측하지 못한다.

### 타깃과 산술적으로 연결된 컬럼을 뺀다

| 제외 | 이유 |
|---|---|
| `tip_amount` | 타깃 그 자체 |
| `total_amount` | **팁을 포함한 합계.** `total − fare − 기타 = tip`으로 역산된다 |
| `payment_type` | 모집단을 1로 고정했으므로 상수 |

`total_amount`를 넣으면 정확도가 0.99를 넘지만 아무것도 예측한 게 아니다.
운행 시작 시점에는 알 수 없는 값이라 실제로 쓸 수 없는 모델이 된다.

### 임계값 25%를 쓴다

| 임계값 | 양성 비율 |
|---|---:|
| 15% | 78.73% |
| 20% | 72.63% |
| **25%** | **56.13%** |

15%로 잡으면 **"전부 양성"이라 찍어도 정확도 0.79**가 나와 실제 모델(0.77)을
이긴다. 25%는 클래스가 56:44로 균형에 가까워 정확도가 의미를 갖는다.

## 2. 구현 단계에서 정한 것

### 결정 M-1. 전처리를 Pipeline 안에 넣는다 ★

**결정**
`ColumnTransformer`(결측 대체 + 스케일링 + 인코딩)와 모델을 하나의
`Pipeline` 객체로 묶는다. 전처리를 Pipeline 밖에서 미리 하지 않는다.

```
Pipeline
├─ pre : ColumnTransformer
│   ├─ num : SimpleImputer(median) → StandardScaler
│   └─ cat : SimpleImputer(most_frequent) → OneHotEncoder(min_frequency=0.005)
└─ clf : HistGradientBoostingClassifier
```

**근거 — 전처리 누수를 구조적으로 막는다**
대체값(중앙값·최빈값)과 스케일링 기준(평균·표준편차)은 **학습 데이터에서만**
계산돼야 한다. 전체 데이터로 미리 처리하면 테스트셋 정보가 학습에 새어 들어가
평가 점수가 실제보다 좋게 나온다.

`Pipeline`은 `fit`에서 학습셋 기준을 학습하고 `transform`에서 그대로 적용하므로
이 실수를 할 수 없게 만든다.

**한계**
Pipeline 안의 전처리는 `predict` 시에도 매번 실행된다. 대량 추론에서는
전처리 결과를 캐시하는 편이 빠르지만, 그러면 누수 방지 이점을 잃는다.

---

### 결정 M-2. `SimpleImputer`를 쓰는 것은 §2의 "결측을 채우지 말라"와 모순이 아니다

**결정** 수치형은 중앙값, 범주형은 최빈값으로 대체한다.

**근거 — 목적이 다르다**

| | 분석용 데이터셋 (문서 §2) | 모델 입력 (여기) |
|---|---|---|
| 목적 | 사실을 왜곡 없이 보존 | 알고리즘이 요구하는 형식 충족 |
| 결측의 의미 | "이 소스는 이 필드를 제출하지 않았다"는 **정보** | 계산 불가능한 값 |
| 채우면 | 통계가 오염된다 (혼잡통행료 평균 2.203 → 1.689) | — |
| 안 채우면 | — | scikit-learn이 예외를 던져 **학습 불가** |

핵심은 **대체된 값이 저장되지 않는다**는 점이다. `SimpleImputer`는 Pipeline
내부에서만 동작하며, `data/processed/`의 정제 데이터는 결측을 그대로 유지한다.

또한 §2가 금지한 것은 **결측을 채워 집계·통계를 왜곡하는 것**이다.
여기서는 집계를 하지 않고 예측만 한다.

**한계**
카드결제 한정 데이터에서 실제 결측은 많지 않아 Imputer는 대부분 안전장치로
동작한다. 다만 다음 달 데이터에 결측이 늘어도 파이프라인이 죽지 않게 한다.

---

### 결정 M-3. 트리 모델에 `StandardScaler`를 넣는다

**결정** 수치형에 스케일링을 적용한다.

**근거**
`HistGradientBoostingClassifier`는 트리 기반이라 **스케일링이 성능에 영향을
주지 않는다.** 그럼에도 넣는 이유는

1. 모델을 로지스틱 회귀 등으로 바꿀 때 전처리를 다시 짜지 않아도 된다.
   설정에서 모델만 교체하면 되도록 한다.
2. 스케일링은 전처리의 기본 구성 요소다. 모델 종류와 무관하게 전처리
   파이프라인의 형태를 일관되게 유지한다.

**반례**
스케일링을 빼고 트리 모델에 최적화했다가 나중에 선형 모델로 바꾸면
피처 스케일 차이(거리 0~100 vs 요금 0~1000) 때문에 학습이 망가진다.

**한계**
불필요한 연산이 추가된다. 50만 행 기준 무시할 수준이다.

---

### 결정 M-4. 평가 지표를 5개 낸다

**결정** accuracy, precision, recall, F1, ROC-AUC.

**근거**

| 지표 | 왜 필요한가 |
|---|---|
| accuracy | 클래스가 56:44로 균형에 가까워 의미가 있다 |
| F1 | 정밀도와 재현율의 조화평균. 한쪽만 좋은 모델을 걸러낸다 |
| precision·recall | F1만으로는 어느 쪽이 부족한지 알 수 없다 |
| ROC-AUC | 임계값 0.5에 의존하지 않는 순위 품질 |

**기준선을 함께 보고한다.** 다수 클래스만 예측하는 더미 모델의 정확도를
같이 내야 실제 모델이 얼마나 나은지 판단할 수 있다.

**한계**
데이터를 무작위로 분할했다. "미래 예측"이 목적이라면 시간 순 분할이 옳다.
한 달치라 시계열 추세가 크지 않아 무작위 분할을 쓴다.

---

### 결정 M-5. 모델 파일을 실행 디렉터리에 저장한다

**결정** `joblib.dump`로 `outputs/runs/<run_id>/model.joblib`에 저장한다.

**근거**
- 실행마다 데이터·설정이 다를 수 있는데 고정 경로에 덮어쓰면
  **어떤 모델이 어떤 데이터로 학습됐는지 추적할 수 없다.**
  `run_id` 디렉터리에 두면 매니페스트의 입력·설정 해시와 자동으로 연결된다.

**저장되는 것**: 전처리까지 포함한 Pipeline 객체 전체.
따라서 불러온 뒤 원본 형태의 DataFrame을 그대로 넣어 예측할 수 있다.

```python
import joblib
model = joblib.load("outputs/runs/<run_id>/model.joblib")
model.predict(df[FEATURES])     # 전처리가 안에 들어 있다
```

**한계**
joblib 파일은 scikit-learn 버전에 민감하다. 버전이 바뀌면 로딩이 실패하거나
경고가 난다. 매니페스트에 라이브러리 버전을 함께 기록한다.

## 3. 설정

```toml
[model]
target_tip_rate = 0.25       # 고액팁 임계값 (STEP 1 §B-3)
payment_type = 1             # 카드결제 한정 (STEP 1 §B-2)
train_sample = 500000        # 층화 추출 크기 (STEP 1 §B-6)
test_size = 0.2
random_state = 42            # 재현성
min_frequency = 0.005        # 범주형 희귀값 병합 (STEP 1 §B-5)
```

## 4. 품질 게이트

| 항목 | 기준 | 이유 |
|---|---|---|
| `f1` | 0.70 ~ 0.95 | 무너지면 데이터 이상, 지나치게 높으면 **누수 의심** |
| `train_rows` | ≥ 100,000 | 필터를 잘못 걸어 데이터가 말라붙는 사고 방지 |

상한을 두는 이유가 중요하다. F1이 0.95를 넘으면 성능이 좋은 게 아니라
**누수가 생겼을 가능성**이 크다. 자동화에서 조용히 넘어가면 안 되는 신호다.
