## 2. 점검 과정에서 발견해 고친 것

### A1이 실제로는 미충족이었다 ★

`polars`가 `run_pipeline.py compare-loaders` **명령에만** 있었다.
`import polars`가 코드에 존재하니 통과로 보이지만, 실제로는

- 기본 실행(`python run_pipeline.py`)에 polars가 **전혀 등장하지 않는다**
- 비교 결과가 **`report.md`에 실리지 않는다**

발표가 없어 리포트가 유일한 전달 수단인데, 요건을 충족하는 내용이
별도 명령 뒤에 숨어 있으면 아무도 보지 못한다.

**조치**: `compare_loaders`를 파이프라인 **첫 단계**로 편입했다.
비용은 parquet을 polars로 한 번 더 읽는 0.097초다.
기존 명령은 터미널에서 상세히 볼 때 쓰는 보조 도구로 남겼다.

**교훈**: "코드에 있다"와 "요건을 충족한다"는 다르다.
검증을 코드 문자열이 아니라 **실행 결과**로 해야 이런 것이 잡힌다.

### 주석 점검 기준을 바꿨다

처음에는 "주석 비율 25% 이상"으로 검사했다. 그러자 코드가 조밀한 파일
(`missing.py` 23.4%, `outliers.py` 24.7%)이 낮게 나왔는데, 실제로는
**모든 함수에 독스트링이 있었다**. 25%라는 숫자는 근거 없는 임의값이었다.

**조치**: "모든 함수·클래스가 자기 설명을 갖는가"로 바꿨다.
그러자 진짜 누락 15곳이 드러났다(`storage.py` 5개, `run_pipeline.py` 2개 등).
전부 채웠다.

### 문서와 코드가 어긋난 곳

`compare-loaders` 명령의 독스트링에 "파이프라인 본체에는 넣지 않았다"고
적혀 있었는데, 단계로 편입하면서 사실과 달라졌다. 정정했다.


## 4. 남아 있는 한계

리포트의 「한계」 섹션에 자동으로 실리는 내용과 동일하다.
숨기지 않고 명시하는 것이 이 과제의 원칙이다.

| 단계 | 한계 |
|---|---|
| `prepare_missing` | partial 소스 955,371행은 행을 남겼지만 승객수·요율·결제수단 컬럼 자체가 없다. 해당 컬럼을 쓰는 분석에서는 자동 제외되므로 **그 결과는 부분집합에 대한 것**이다 |
| `filter_outliers` | 소요시간 규칙이 `VendorID=7`(51,750건)을 전량 제거한다. 값이 이상한 게 아니라 기록 방식이 다른 것이므로, 운행량 분석이 목적이면 `duration_policy='flag'`로 바꿔야 한다 |
| `statistics` | 같은 기사·차량의 반복 운행으로 관측이 완전히 독립이 아니다. p-value가 실제보다 작게 나오며, 식별자가 없어 보정 불가 |
| `model` | 무작위 분할이라 "미래 예측" 성능은 과대평가될 수 있다. 하이퍼파라미터 미튜닝 |

- 시간 순 학습/평가 분할
