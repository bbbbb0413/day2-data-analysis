## 1. 결론

**가능하다.** 그리고 대부분은 *동작을 바꾸지 않는* 순수 정리 작업이다.

- 삭제 가능한 순중복이 **약 270줄**(`report.py`의 리포트 렌더러 2개 중 1개) +
  **CLI가 다시 구현한 로딩 비교 판정 로직**(줄 수는 비슷하지만 판정이 두 곳에
  있어 기준을 바꿀 때 양쪽을 고쳐야 한다) 있다.
- 파이프라인 단계 함수는 이미 `(DataFrame, Config) -> StepResult` 순수 함수 계약을
  지키고 있어 **구조의 뼈대는 건강하다.** 손댈 곳은 뼈대가 아니라
  ⓐ 리포트 계층, ⓑ 저장소 루트, ⓒ 협업 흔적 주석, ⓓ 공용 상수의 산재다.
- 숫자를 만드는 로직(`missing`/`duplicates`/`outliers`/`statistics`/`model`)은
  **한 줄도 건드리지 않는다.** 따라서 골든 파일 비교로 무결성을 기계적으로 검증할 수 있다.

요청 ①은 `render_report()` 삭제 + `render_report_revised()` 개명 + `runner` 호출부 정리로
끝난다(약 30분). 리포트에서 빠지는 블록은 §3.1에 기록만 남기고 복원하지 않는다.

### 리팩토링 원칙

| 원칙 | 이유 |
|---|---|
| 지표를 만드는 코드는 건드리지 않는다 | `metrics.json`이 바이트 단위로 같아야 검증이 성립한다 |
| 한 커밋 = 한 종류의 변경 | "정리하다 로직이 바뀐" 사고를 diff에서 잡을 수 있다 |

| 파일명 `report.md`는 고정 | 채점 기준 C1이 파일명을 명시한다(`docs/05` §검증 방법) |

```python
def run_pipeline(cfg, *, steps=None, checkpoint=False, save_output=True,
                 input_path=None, force_download=False) -> RunResult:
    src  = _resolve_input(cfg, input_path, force_download)   # 준비 + 스키마 검증
    run  = _begin_run(cfg, src)                              # run_id · store · manifest

        _save_processed(df, cfg, run, save_output)
        _finalize(cfg, run)                                  # 게이트 → metrics.json → report.md
    except Exception:
        ...
    finally:
        _close_manifest(run)                                 # 시각 계산은 여기 한 곳만
```

### Phase 9 — Plotly PNG 내보내기 제거 (Chrome 의존 해소) · 40분

§3.16 해결. 얻는 것: **실행 6초 단축**, **Chrome 의존성 제거**, 로그 40줄 감소,
`requirements.txt`에서 `kaleido` 제거.

#### ① PNG 내보내기를 설정으로 끈다

```toml
# config/pipeline.toml [visualize]
# Plotly 차트를 PNG로도 내보낼지. true면 kaleido가 Chrome을 띄워 렌더링하므로
# 실행이 6초 늘고 Chrome이 없는 환경에서는 실패한다. 리포트가 HTML 링크만
# 쓴다면 false로 둔다.
plotly_export_png = false
```

```python
# steps/visualize.py  _plotly()
def _plotly(fig, name: str, caption: str, export_png: bool) -> Artifact:
    """Plotly Figure를 HTML(+선택적 PNG) 산출물로 변환한다."""
    def save(path: Path) -> None:
        fig.write_html(str(path.with_suffix(".html")), include_plotlyjs="cdn")
        if export_png:
            fig.write_image(str(path), scale=2)
    # PNG를 안 만들면 파일명도 .html로 둬야 manifest 경로가 실제 파일을 가리킨다
    return Artifact(name=name if export_png else name.replace(".png", ".html"),
                    save=save, caption=caption, kind="plotly")
```

**`Artifact.name`을 함께 바꾸는 것이 핵심이다.** `runner.py`가 `art.name`으로 저장 경로와
`manifest.outputs`를 만들기 때문에, PNG를 안 만들면서 이름을 `.png`로 두면
**존재하지 않는 파일을 가리키는 매니페스트**가 된다.

`figure_count` 게이트는 `len(artifacts)`를 세므로 **10 그대로**다 — 게이트 수정 불필요.

#### ② 서드파티 로그 억제 (PNG를 유지하더라도 별개로 적용)

```python
# observability.py  setup_logging()
for noisy in ("kaleido", "choreographer", "matplotlib", "PIL"):
    logging.getLogger(noisy).setLevel(logging.WARNING)
```

#### ③ 산출물 저장 실패를 삼키지 않되 죽지도 않게

`runner.py`의 산출물 저장 루프를 `try/except`로 감싸 **한 차트 저장 실패가 파이프라인
전체를 죽이지 않게** 한다. 대신 실패를 `manifest`에 기록하고 `log.error`를 남긴다.
(§3.16의 "Chrome 없는 서버에서 파이프라인 실패" 시나리오 방어)

#### 판단이 필요한 부분

- **외부에서 준비하는 리포트가 마크다운이라면 PNG가 필요하다** — 마크다운은 인터랙티브
  HTML을 임베드할 수 없다. 그 리포트에 Plotly 차트를 그림으로 넣을 계획이면
  `plotly_export_png = true`로 두고 ②·③만 적용한다.
- HTML은 `include_plotlyjs="cdn"`이라 **오프라인에서 빈 화면**이 된다. HTML만 남기기로
  하면 `include_plotlyjs=True`(파일당 약 3MB 증가) 전환도 함께 검토한다.

**검증**
```bash

NEW=$(ls -td outputs/runs/*/ | head -1)

```
